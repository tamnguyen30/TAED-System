Before linking a review snapshot:

1. Choose and record the exact release commit. Export a clean snapshot without `.git` history.
2. Include only the implementations and results actually described, with explicit labels for comparison variants.
3. Inspect README files, package metadata, comments, paths, logs, notebooks, figures/PDF metadata, links, model cards, and dataset metadata for author identifiers or private information. Preserve legally required notices; if they identify authors, explain the artifact limitation or choose an appropriate distribution route.
4. Provide a README, environment instructions, artifact inventory, and experiment-to-result mapping. List missing or restricted assets explicitly.
5. Open the anonymous link while signed out and verify files and downloads. Ensure it does not redirect to an identified repository.
6. Describe only the files actually included in the paper's availability statement. Do not claim all results are reproducible until the necessary assets and commands have been exercised.

Do not publish participant-level study records or redistribute source corpora without the applicable consent and permissions. Aggregated results and source acquisition instructions can be documented separately.
